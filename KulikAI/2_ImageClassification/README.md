# Практическая работа №2 — классификация изображений с BoW

## 1. Цель работы

Разработать приложение для классификации фотографий архитектурных достопримечательностей на основе подхода **Bag of Visual Words (BoW, мешок визуальных слов)**. Приложение поддерживает классические локальные дескрипторы OpenCV, признаки сверточных нейронных сетей PyTorch и несколько методов машинного обучения.

Реализованы пять способов извлечения признаков:

| Тип | Метод | Размерность одного дескриптора | Источник признаков |
|---|---|---:|---|
| Классический | SIFT | 128 | Локальные ключевые точки OpenCV |
| Классический | KAZE | 64 | Локальные ключевые точки OpenCV |
| CNN | ResNet18 | 512 | Пространственная карта последнего сверточного блока `layer4` |
| CNN | ResNet50 | 2048 | Пространственная карта последнего сверточного блока `layer4` |
| CNN | MobileNetV3 Small | 576 | Пространственная карта `features` перед глобальным pooling |

Для классификации BoW-гистограмм доступны SVM (по умолчанию), Random Forest и k-NN.

## 5. Общий принцип Bag of Visual Words

Пусть для изображения извлечено множество локальных дескрипторов:

$$
D = \{d_1,d_2,\ldots,d_N\}, \qquad d_i\in\mathbb{R}^{p}.
$$

### 5.1. Построение визуального словаря

Дескрипторы тренировочных изображений объединяются в общую матрицу. Метод K-средних делит их на $K$ кластеров. Центр каждого кластера интерпретируется как визуальное слово:

$$
V=\{\mu_1,\mu_2,\ldots,\mu_K\}.
$$

На каждой итерации K-means выполняются два шага:

1. **Назначение кластеров:** каждый дескриптор относится к ближайшему центру по евклидову расстоянию:

$$
q(d_i)=\arg\min_{j\in\{1,\ldots,K\}}\|d_i-\mu_j\|_2^2.
$$

2. **Обновление центров:** центр кластера пересчитывается как среднее его дескрипторов:

$$
\mu_j=\frac{1}{|C_j|}\sum_{d_i\in C_j}d_i.
$$

Шаги повторяются до сходимости или достижения максимального числа итераций. В реализации используется `sklearn.cluster.KMeans`. Параметр `--max-descriptors` ограничивает число дескрипторов, случайно отбираемых для построения словаря, чтобы контролировать потребление памяти.

### 5.2. Построение BoW-гистограммы

После построения словаря все дескрипторы изображения назначаются ближайшим визуальным словам. Для изображения подсчитывается число дескрипторов, попавших в каждый кластер:

$$
h_j=\sum_{i=1}^{N}\mathbb{1}[q(d_i)=j],\qquad j=1,\ldots,K.
$$

Полученная гистограмма нормализуется по L1-норме:

$$
\hat h_j=\frac{h_j}{\sum_{r=1}^{K}h_r}.
$$

Таким образом, сумма элементов ненулевой гистограммы равна единице. Если дескрипторы не найдены, возвращается нулевая гистограмма.

### 5.3. Обучение классификатора

Для каждого тренировочного изображения строится вектор $\hat h$. Матрица гистограмм используется как вход классификатора, а метка каталога изображения — как целевая переменная. Поддерживаются:

- **SVM** (`SVC`, RBF-ядро) — классификатор по умолчанию;
- **Random Forest** (`RandomForestClassifier`);
- **k-NN** (`KNeighborsClassifier`, 5 соседей с весами по расстоянию).

Словарь K-means и обученный классификатор сохраняются вместе в одном файле модели `.joblib`.

## 6. Реализация извлечения признаков

### 6.1. Классические методы OpenCV

**SIFT (`SIFTExtractor`).** Изображение переводится в оттенки серого, после чего `cv2.SIFT_create().detectAndCompute` обнаруживает ключевые точки и вычисляет для каждой 128-мерный дескриптор. SIFT строится с учетом масштаба и ориентации локальной области.

**KAZE (`KAZEExtractor`).** Изображение также переводится в оттенки серого. `cv2.KAZE_create().detectAndCompute` использует нелинейное масштабное пространство и формирует 64-мерные вещественные дескрипторы (режим `extended=False`).

Оба метода извлекают множество дескрипторов различной длины для разных изображений. Это множество непосредственно используется как набор наблюдений для построения BoW-гистограммы.

### 6.2. CNN-модели PyTorch

Для CNN используется единая предобработка, согласованная с ImageNet-весами torchvision:

1. OpenCV-изображение в формате BGR переводится в RGB.
2. Изображение преобразуется в PIL.
3. Масштабируется так, чтобы меньшая сторона имела размер 256 пикселей.
4. Из центра вырезается область 224×224.
5. Значения пикселей переводятся в тензор с диапазоном `[0, 1]`.
6. Каждый канал нормализуется параметрами ImageNet:

$$
\mu=(0.485,0.456,0.406),\qquad
\sigma=(0.229,0.224,0.225),
$$

$$
x'_c=\frac{x_c-\mu_c}{\sigma_c}.
$$

Модели работают в режиме `eval()` и без вычисления градиентов (`torch.inference_mode()`). Полносвязный классификационный слой и глобальный pooling не используются: извлекается пространственная карта признаков, чтобы получить набор локальных дескрипторов.

**ResNet18 (`ResNet18Extractor`).** Используются слои от `conv1` до `layer4` включительно. Для входа 224×224 получается карта признаков размера 512×7×7. Ее 49 пространственных позиций преобразуются в 49 дескрипторов размерности 512.

**ResNet50 (`ResNet50Extractor`).** Используется та же схема извлечения до `layer4`, но более глубокая архитектура ResNet-50. Для входа 224×224 получается карта признаков размера 2048×7×7. Ее 49 пространственных позиций преобразуются в 49 дескрипторов размерности 2048. По сравнению с ResNet18 каждый дескриптор в четыре раза шире, поэтому увеличиваются требования к оперативной памяти и вычислительной нагрузке K-means.

**MobileNetV3 Small (`MobileNetV3SmallExtractor`).** Используется сверточная часть `features` модели до глобального pooling. Для входа 224×224 получается карта признаков 576×7×7; после перестановки осей и преобразования формы она дает 49 дескрипторов размерности 576.

В результате для CNN действует тот же BoW-пайплайн, что и для SIFT/KAZE: пространственные векторы объединяются, кластеризуются K-means и кодируются нормализованной гистограммой.

## 8. Запуск приложения

Все команды выполняются из директории `2_ImageClassification` при активированном окружении `cv_lab2`.

### 8.1. Обучение (`train`)

Пример обучения SIFT + SVM:

```bat
python main.py train --dataset "D:\datasets\Architecture" --extractor sift --classifier svm --clusters 128 --model-out models\sift_svm.joblib
```

Пример обучения KAZE + Random Forest:

```bat
python main.py train --dataset "D:\datasets\Architecture" --extractor kaze --classifier random_forest --clusters 128 --model-out models\kaze_rf.joblib
```

Пример обучения ResNet18 + SVM:

```bat
python main.py train --dataset "D:\datasets\Architecture" --extractor resnet18 --classifier svm --clusters 128 --device auto --model-out models\resnet18_svm.joblib
```

Пример обучения ResNet50 + SVM (рекомендуемая конфигурация по результатам проведенных экспериментов):

```bat
python main.py train --dataset "D:\datasets\Architecture" --extractor resnet50 --classifier svm --clusters 128 --max-descriptors 20000 --device auto --model-out models\resnet50_svm.joblib
```

Для ResNet50 в README рекомендуется ограничить выборку дескрипторов для K-means значением `30000`: размерность каждого дескриптора равна 2048, поэтому кластеризация заметно тяжелее, чем у ResNet18. Это ограничение относится к выборке K-means; сама текущая train-реализация пока держит дескрипторы тренировочных изображений в RAM до построения словаря.

Пример обучения MobileNetV3 Small:

```bat
python main.py train --dataset "D:\datasets\Architecture" --extractor mobilenet_v3_small --classifier svm --clusters 128 --device auto --model-out models\mobilenet_svm.joblib
```

Параметры:

- `--extractor`: `sift`, `kaze`, `resnet18`, `resnet50`, `mobilenet_v3_small`;
- `--classifier`: `svm`, `random_forest`, `knn`;
- `--clusters`: количество визуальных слов, по умолчанию 128;
- `--max-descriptors`: максимум дескрипторов для K-means, по умолчанию 100000; `0` отключает ограничение;
- `--seed`: начальное значение генератора случайных чисел;
- `--device`: `auto`, `cpu`, `cuda`, `cuda:0` и т. п.;
- `--no-external`: не использовать изображения из `ExtDataset`;
- `--exclude-other`: исключить класс `00_Other`;
- `--no-pretrained`: не загружать ImageNet-веса CNN (не рекомендуется для оценки качества).

Результат `train` — файл модели, включающий словарь визуальных слов, классификатор, сведения о конфигурации извлекателя и веса CNN (для CNN-экстракторов). Поэтому при последующей загрузке сохраненной CNN-модели не требуется повторно скачивать веса ImageNet.

### 8.2. Тестирование (`test`)

```bat
python main.py test --dataset "D:\datasets\Architecture" --model models\resnet50_svm.joblib --device cuda --save-results outputs\resnet50_test.csv --save-confusion-matrix outputs\resnet50_confusion.png
```

В режиме `test` изображения обрабатываются по одному: дескрипторы сразу кодируются обученным K-means и передаются классификатору. Это не позволяет накапливать дескрипторы всей тестовой выборки в оперативной памяти. Для ResNet50 это особенно важно из-за размерности 2048.

Пайплайн загружает модель, извлекает признаки изображений из `test`, строит гистограммы и вычисляет:

- `accuracy` — долю правильно классифицированных изображений;
- `precision`, `recall`, `f1-score` по каждому классу и усредненные значения.

Опциональный CSV содержит путь к изображению, истинную метку, предсказанную метку и признак правильности. Матрица ошибок сохраняется в PNG.

При тестировании параметры выбора источников и `00_Other` должны соответствовать режиму обучения. По умолчанию используются оба источника и все классы.

### 8.3. Классификация одного изображения (`predict`)


В консоль выводится предсказанный класс. В каталоге `outputs\prediction` сохраняются:

- `bow_histogram.png` — гистограмма визуальных слов;
- `image_and_histogram.png` — входное изображение и его BoW-гистограмма.

Для отображения графиков в интерактивном окне добавьте `--show`.

## 9. Последовательность работы программы

**Обучение:**

1. Разбор аргументов командной строки.
2. Загрузка списка изображений и меток из `trainval`.
3. Создание извлекателя признаков через `FeatureExtractor.create`.
4. Извлечение локальных дескрипторов для каждого тренировочного изображения.
5. Построение словаря визуальных слов с помощью K-means.
6. Кодирование каждого изображения нормализованной BoW-гистограммой.
7. Обучение классификатора на полученных гистограммах и сохранение модели.

**Тестирование:**

1. Загрузка обученной модели и создание соответствующего извлекателя.
2. Загрузка изображений и истинных меток из `test`.
3. Извлечение дескрипторов, кодирование гистограмм и предсказание классов.
4. Расчет accuracy и отчета классификации; при необходимости сохранение CSV и матрицы ошибок.

**Предсказание одного изображения:**

1. Загрузка модели и входного изображения.
2. Извлечение дескрипторов и построение нормализованной BoW-гистограммы.
3. Получение предсказанного класса.
4. Сохранение гистограммы и совместной визуализации изображения с гистограммой.

Во всех трех режимах используется журналирование через стандартный пакет `logging`. Ошибки чтения изображений, отсутствующие директории и некорректные параметры обрабатываются с выводом диагностического сообщения.

## 10. Ограничения и практические замечания

- CNN-модели требуют PyTorch и torchvision; классические извлекатели работают на CPU через OpenCV.
- ResNet50 формирует 49 дескрипторов размерности 2048 для каждого изображения 224×224. Это в четыре раза больше значений на изображение, чем у ResNet18; учитывайте это при выборе объема обучающей выборки K-means.
- В `test` CNN-дескрипторы не накапливаются для всей выборки: каждый файл обрабатывается последовательно, что снижает потребление RAM.
- Для CNN при первом запуске обычно требуется скачать предобученные веса ImageNet. На CPU извлечение признаков может занять значительное время.
- Количество кластеров не может превышать число отобранных дескрипторов; если дескрипторов меньше `--clusters`, размер словаря автоматически уменьшается.
- Обучение, тестирование и предсказание должны использовать один и тот же метод извлечения признаков, что обеспечивается метаданными сохраненной модели.

## 11. Поврежденные или нечитаемые изображения

Во время `train` и `test` приложение пропускает изображения, которые не удалось прочитать или декодировать OpenCV. Для каждого такого файла в журнал выводится предупреждение с его путем и причиной ошибки. После обработки выводится количество успешно обработанных и пропущенных изображений. Метки классов формируются только по успешно прочитанным изображениям, поэтому пропуск файла не нарушает соответствие между дескрипторами и метками.

Это позволяет продолжить эксперимент, если в датасете встретился поврежденный JPEG/PNG. Однако пропущенные файлы не участвуют в обучении или оценке качества. Для итогового эксперимента желательно заменить или восстановить такие изображения и повторить запуск. В режиме `predict` ошибка чтения одиночного входного изображения по-прежнему считается фатальной: без изображения предсказание выполнить невозможно.

Сообщение OpenCV `Corrupt JPEG data: premature end of data segment` обычно указывает на неполные или поврежденные данные JPEG. Само предупреждение может сопровождать частичное декодирование; если OpenCV не вернул изображение, файл будет пропущен.
