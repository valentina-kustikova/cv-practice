# Практическая работа №2. Классификация изображений с использованием библиотеки OpenCV

Приложение для классификации изображений на основе подхода **«мешок визуальных слов» (Bag-of-Words, BoW)**. Признаки извлекаются классическими методами библиотеки OpenCV (SIFT, ORB) и с промежуточных слоёв нейросетей средствами PyTorch (ResNet-18, MobileNetV2); поверх BoW-гистограмм обучаются классические методы машинного обучения (SVM, Random Forest, kNN).

---

## 1. Постановка задачи

Цель — разработать приложение, которое классифицирует изображения (архитектурные сооружения разных городов РФ в исходной задаче) по подходу «мешок визуальных слов»:

1. с каждого изображения извлекаются **локальные дескрипторы** (классические методы OpenCV или признаки промежуточного слоя CNN, используемые как «плотные локальные дескрипторы»);
2. все дескрипторы обучающей выборки **кластеризуются методом K-средних** — центроиды кластеров образуют **словарь визуальных слов**;
3. каждое изображение описывается **нормированной гистограммой частот визуальных слов**;
4. на гистограммах обучается **классификатор** (SVM / Random Forest / kNN);
5. модель (словарь + классификатор + параметры экстрактора) сохраняется в один файл.

Скрипт поддерживает три режима:

| Режим | Действия | Результат |
|---|---|---|
| `train` | построение словаря K-средними, гистограммы обучающей выборки, обучение классификатора | файл модели (pickle) |
| `test` | загрузка модели, классификация тестовой выборки | точность, отчёт по классам, опционально CSV с результатами и txt-отчёт |
| `predict` | загрузка модели, BoW-гистограмма одного изображения, классификация | предсказанный класс, график гистограммы и изображение с гистограммой (PNG) |


## 2. Общая схема решения

```
                    ┌───────────────────────────────  РЕЖИМ TRAIN  ────────────────────────────────┐
 изображения trainval ─► экстрактор признаков ─► дескрипторы (N_i × D)
                                                        │
                          все дескрипторы ─► K-средних (MiniBatchKMeans) ─► словарь: V центроидов
                                                        │
                    дескрипторы ─► ближайшее слово ─► гистограмма (V) ─► нормировка L1
                                                        │
                    гистограммы + метки ─► классификатор (SVM / RF / kNN) ─► сохранение модели .pkl
                    └──────────────────────────────────────────────────────────────────────────────┘
                    ┌───────────────────────────────  РЕЖИМ TEST  ─────────────────────────────────┐
 изображения test ─► экстрактор (из модели) ─► дескрипторы ─► гистограммы ─► предсказания
                                                        │
                    метрики: accuracy, отчёт по классам (precision/recall/F1), матрица ошибок,
                    файлы results.csv, report.txt
                    └──────────────────────────────────────────────────────────────────────────────┘
                    ┌───────────────────────────────  РЕЖИМ PREDICT  ──────────────────────────────┐
 одно изображение ─► экстрактор (из модели) ─► дескрипторы ─► гистограмма ─► класс + уверенность
                                                        │
                    PNG-файлы: <имя>_bow_histogram.png, <имя>_image_with_histogram.png
                    └──────────────────────────────────────────────────────────────────────────────┘
```

## 3. Набор данных (дерево папок, любая глубина вложенности)

Загрузчик `FolderDataLoader` (`src/data.py`) сканирует каталоги выборок **рекурсивно** и считает классом любой каталог, непосредственно содержащий файлы изображений. Поддерживаются две структуры (и их комбинация).

Плоская структура:

```
<data-root>/
├── trainval/
│   ├── <имя_класса_1>/*.jpg, *.png, ...
│   ├── <имя_класса_2>/...
│   └── ...
└── test/
    ├── <имя_класса_1>/...
    └── ...
```

Вложенная структура (с поднаборами, как в наборе по ссылке):

```
<data-root>/
├── trainval/
│   ├── ExtDataset/              <-- поднабор (классом НЕ считается)
│   │   ├── <имя_класса_1>/...
│   │   └── <имя_класса_2>/...
│   └── NNSUDataset/
│       ├── <имя_класса_3>/...
│       └── ...
└── test/
    ├── ExtDataset/...
    └── NNSUDataset/...
```

Особенности:

* класс — каталог, непосредственно содержащий изображения; поддерживаемые расширения: jpg, jpeg, png, bmp, tif, tiff, webp; поднаборы (промежуточные каталоги без изображений) и скрытые каталоги (`.ipynb_checkpoints` и т. п.) классами не считаются;
* одноимённые классы из разных поднаборов **объединяются** в один класс (`ExtDataset/театр` и `NNSUDataset/театр` — один класс `театр`);
* `--max-per-class N` ограничивает число изображений **на класс суммарно** по всем поднаборам;
* метки классов назначаются по **алфавитно отсортированному** списку имён классов, поэтому метки в trainval и test всегда согласованы; при несовпадении набора классов выдаётся ошибка с перечнем отсутствующих и лишних классов;

## 4. Использованные алгоритмы

### 4.1. Классические дескрипторы (OpenCV)

**SIFT** (`SiftExtractor`, cv2.SIFT_create). Ключевые точки ищутся в пирамиде разностей гауссианов (DoG) — инвариантность к масштабу; область точки нормируется по доминирующему направлению — инвариантность к повороту; дескриптор — 128-мерный вектор гистограмм градиентов (сетка 4×4 ячейки по 8 направлений), частично устойчив к изменениям освещённости. Параметр `nfeatures` (по умолчанию 2000) ограничивает число точек на изображение.

**ORB** (`OrbExtractor`, cv2.ORB_create). Ключевые точки — детектор FAST, дескриптор — бинарная строка BRIEF из 256 бит (хранится как 32 байта uint8) с коррекцией ориентации (Rotated BRIEF). ORB в десятки раз быстрее SIFT. Так как K-средних использует евклидово расстояние, бинарные дескрипторы переводятся в float32: квадрат евклидова расстояния между 0/1-векторами равен расстоянию Хэмминга, поэтому кластеризация корректна.

Параметр `min_side` (классические экстракторы): если меньшая сторона изображения меньше заданного значения, изображение пропорционально увеличивается перед детектированием — на мелких изображениях детекторы находят слишком мало точек.

### 4.2. Нейросетевые извлекатели признаков (PyTorch)

**Ключевая идея.** Выход свёрточного слоя имеет форму `(C, H, W)` — каждый из H·W векторов длины C описывает локальную область исходного изображения. Поэтому карта признаков трактуется как **H·W плотных локальных дескрипторов размерности C** и поступает в общий BoW-конвейер: K-средних → гистограмма.

Выходной слой сети отключается: берётся **промежуточный свёрточный слой**, признаки с которого являются фиксированными (сеть работает в режиме инференса, без дообучения).

#### ResNet-18 (`ResNet18Extractor`)

* Модель: `torchvision.models.resnet18(weights=ResNet18_Weights.IMAGENET1K_V1)` (≈11,7 млн параметров, обучена на ImageNet). Residual-блоки.
* Используемый слой: `model.layer4` — последний residual-блок. Для входа 224×224 выход имеет форму **(512, 7, 7)** → **49 дескрипторов по 512 элементов**.
* **Предобработка изображений** (метод `_preprocess`, единый для обеих моделей):
  1. приведение к трём каналам (серое → BGR) и переход BGR → RGB (модель обучена на RGB);
  2. изменение размера до `input_size`×`input_size` (224×224, интерполяция INTER_LINEAR) — детерминированная квадратная сетка позиций, всё изображение сохраняется (в отличие от CenterCrop);
  3. перевод в тензор float32 и масштабирование пикселей в [0, 1] (деление на 255);
  4. нормализация каналов средним и СКО ImageNet: mean = (0.485, 0.456, 0.406), std = (0.229, 0.224, 0.225). Это распределение входа, на котором обучались веса модели; без нормализации признаки «уплывают».
* **Обработка выхода сети** (постобработка): выход слоя (1, 512, 7, 7) через forward-hook; отбрасывается размерность батча, `(512, 7, 7)` транспонируется в `(7, 7, 512)` и разворачивается в матрицу **(49, 512)**; каждый дескриптор **нормируется по L2** — евклидово расстояние K-средних становится сравнимым с косинусным, что стабилизирует кластеризацию.
* Сеть переводится в режим `eval()` (BatchNorm использует накопленные статистики, Dropout отключён) и работает под `torch.no_grad()` (градиенты не нужны, экономия памяти).

#### MobileNetV2 (`MobileNetV2Extractor`)

* Модель: `torchvision.models.mobilenet_v2(weights=MobileNet_V2_Weights.IMAGENET1K_V1)` (≈3,5 млн параметров). Построена на depthwise separable-свёртках и inverted residual-блоках с линейными bottleneck-слоями — заметно легче и быстрее ResNet-18.
* Используемый слой: `model.features[-1]` — последний свёрточный блок (1280 каналов). Для входа 224×224 выход имеет форму **(1280, 7, 7)** → **49 дескрипторов по 1280 элементов**.
* **Предобработка** — идентична ResNet-18 (RGB, resize до `input_size`, /255, нормализация ImageNet).
* **Обработка выхода** — идентична ResNet-18: (1280, 7, 7) → матрица (49, 1280) → L2-нормировка каждого дескриптора.

#### Сравнение реализованных экстракторов

| Экстрактор | Тип | Размерность дескриптора | Дескрипторов на 224×224 | Скорость | Нужен интернет |
|---|---|---|---|---|---|
| `sift` | классика (OpenCV) | 128 | до `nfeatures` (2000) | средняя | нет |
| `orb` | классика (OpenCV) | 32 (256 бит) | до `nfeatures` (2000) | очень высокая | нет |
| `resnet18` | CNN (PyTorch) | 512 | 49 | высокая (GPU/CPU) | да, при первом запуске (веса ImageNet) |
| `mobilenetv2` | CNN (PyTorch) | 1280 | 49 | высокая | да, при первом запуске |

`--no-pretrained` отключает загрузку ImageNet-весов (случайная инициализация).

### 4.3. Словарь визуальных слов и BoW-гистограммы (`BagOfWords`)

* **Кластеризация** — `MiniBatchKMeans` (sklearn): полный K-means на сотнях тысяч дескрипторов слишком медленный; мини-пакетный вариант обрабатывает дескрипторы порциями (`batch_size` = 1024) и даёт сопоставимое качество. Параметры: `n_init=3`, `max_iter=200`, `random_state` фиксирован (воспроизводимость). Если дескрипторов больше `--vocab-sample-size` (по умолчанию 150 000), словарь строится по случайной подвыборке. Если дескрипторов меньше, чем слов в словаре, размер словаря автоматически уменьшается с предупреждением.
* **Назначение слов** — для каждого дескриптора изображения методом `kmeans.predict` находится ближайший центроид (визуальное слово); `np.bincount` строит гистограмму частот слов длины V.
* **Нормировка** — по умолчанию **L1** (сумма гистограммы = 1): устраняет зависимость от числа ключевых точек на изображении (у крупных изображений точек больше, но «профиль» слов тот же). Опции: `l2`, `none` (`--hist-norm`).
* Изображения, для которых не найдено ни одного дескриптора, получают нулевую гистограмму и корректно обрабатываются (в обучении пропускаются, с предупреждением в логе).

### 4.4. Классификаторы поверх гистограмм

Выбор метода — аргумент `--classifier`:

| Метод | Реализация | Настройки | Когда уместен |
|---|---|---|---|
| `svm` (по умолчанию) | `SVC(kernel='rbf', C=10, gamma='scale', probability=True)` | RBF-ядро хорошо разделяет высокоразмерные гистограммы; `probability=True` включает оценку уверенности в режиме predict | обычно лучший баланс качества |
| `rf` | `RandomForestClassifier(n_estimators=300, n_jobs=-1)` | ансамбль решающих деревьев, устойчив к масштабу признаков, быстрое обучение | быстрый baseline, без настройки |
| `knn` | `KNeighborsClassifier(n_neighbors=5, weights='distance')` | классификация по ближайшим гистограммам | простой baseline, интерпретируемость |

Модель `train` → сохранение: файл pickle содержит словарь (объект MiniBatchKMeans), обученный классификатор, имя и параметры экстрактора, нормировку гистограмм и имена классов. Это гарантирует, что `test`/`predict` выполняют **ровно то же извлечение признаков**, что и обучение.

## 5. Запуск приложения

### 5.1. Установка

```bash
python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt
```


### 5.2. Команды

```bash
python main.py train --data-root ./Dataset --extractor orb --vocab-size 100 --classifier rf --max-per-class 10

python main.py train --dataset ./Dataset --extractor resnet18 --vocab-size 500

python main.py test --data-root ./Dataset --results-out ./outputs/results.csv --report-out ./outputs/report.txt

python main.py predict --image ./Dataset/test/<класс>/photo.jpg --output-dir ./outputs
```


### 5.3. Параметры командной строки

Общие (все режимы; в `test`/`predict` параметры экстрактора берутся из файла модели):

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--extractor` | `sift` | метод извлечения признаков: `sift`, `orb`, `resnet18`, `mobilenetv2` |
| `--dataset` | `folder` | тип источника данных (`folder`) или прямой путь к каталогу набора (`--dataset ./Dataset` ≡ `--data-root ./Dataset`) |
| `--model-path` | `./models/bow_model.pkl` | файл модели |
| `--max-per-class` | 0 (все) | ограничение изображений на класс (суммарно по поднаборам; быстрые прогоны) |
| `--min-side` | 0 | увеличение мелких изображений перед классическим детектором |
| `--cnn-size` | 224 | размер входа нейросети |
| `--device` | `auto` | устройство CNN: `auto`, `cpu`, `cuda` |
| `--no-pretrained` | выкл. | не загружать ImageNet-веса (работа без интернета) |
| `--seed` | 42 | зерно случайности |
| `--log-level` | `INFO` | уровень логирования |

Режим `train`:

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `--vocab-size` | 200 | размер словаря визуальных слов (число кластеров) |
| `--classifier` | `svm` | метод обучения: `svm`, `rf`, `knn` |
| `--hist-norm` | `l1` | нормировка гистограмм: `l1`, `l2`, `none` |
| `--vocab-sample-size` | 150000 | макс. число дескрипторов для построения словаря (0 — все) |
| `--max-descriptors-per-image` | 0 | ограничение дескрипторов с одного изображения (0 — без ограничения) |

Режим `test`: `--results-out` (CSV по каждому изображению), `--report-out` (txt-отчёт с точностью, метриками по классам и матрицей ошибок).

Режим `predict`: `--image` (путь к изображению, обязательный), `--output-dir` (каталог графиков, по умолчанию `./outputs`), `--show` (показать окна matplotlib в дополнение к сохранению).

### 5.5. Результаты каждого режима

* `train` → файл модели `models/bow_model.pkl` (словарь + классификатор + параметры экстрактора + имена классов).
* `test` → в логе: точность, отчёт по классам (precision/recall/F1), матрица ошибок; опционально `results.csv` (столбцы: изображение; истинный класс; предсказанный класс; верно) и `report.txt`.
* `predict` → предсказанный класс и уверенность в логе; файлы `<имя>_bow_histogram.png` и `<имя>_image_with_histogram.png` в каталоге `outputs/`.
