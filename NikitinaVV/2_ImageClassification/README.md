# Практическая работа №2. Классификация изображений с использованием библиотеки OpenCV

Приложение классифицирует фотографии достопримечательностей городов РФ методом мешка визуальных
слов (bag-of-words, BoW). Локальные признаки извлекаются двумя классическими методами OpenCV
(SIFT, ORB) и двумя сверточными сетями PyTorch (ResNet-50, EfficientNet-B0). Словарь строится
методом K-средних, классификатор берется из scikit-learn.

## Постановка задачи

По фотографии нужно определить, какая из 28 достопримечательностей на ней изображена, или отнести
ее к классу `00_Other` (объект не относится ни к одной достопримечательности). Всего 29 классов.

Изображение описывается BoW-гистограммой. Из него извлекается набор локальных дескрипторов,
каждый дескриптор заменяется номером ближайшего визуального слова из словаря, и считается, какую
долю дескрипторов получило каждое слово. Получается вектор фиксированной длины K, на векторах
обучающей выборки обучается классификатор.

## Метод мешка визуальных слов

### Обучение (`run_train`)

1. Из обучающей выборки случайно выбираются `--vocab-images` изображений (по умолчанию 500).
   С каждого берется не больше `--max-descriptors / --vocab-images` = 400 случайных дескрипторов,
   поэтому все изображения дают в словарь одинаковый вклад и K-средних работает не больше чем
   с 200 000 векторами.
2. Для CNN дескрипторы проецируются на 128 главных компонент (PCA, см. ниже).
3. Методом K-средних строится словарь из K визуальных слов (по умолчанию K = 1000).
4. Для каждого обучающего изображения вычисляется BoW-гистограмма.
5. На матрице гистограмм 1333 × K обучается классификатор.
6. В файл модели (`joblib`) сохраняются имя и параметры экстрактора, словарь, параметры PCA,
   обученный классификатор и имена классов. При загрузке экстрактор создается заново фабричным
   методом `FeatureExtractor.create`, поэтому `test` и `predict` берут все параметры из модели.

### Словарь: метод K-средних (`BagOfWords.build_vocabulary`)

Для дескрипторов $x_1, \dots, x_M$ ищутся центры $c_1, \dots, c_K$, минимизирующие сумму
квадратов расстояний до ближайшего центра:

$$J = \sum_{i=1}^{M} \min_{k} \lVert x_i - c_k \rVert^2 .$$

Используется `cv2.kmeans`: начальные центры выбираются по схеме k-means++ (каждый следующий центр
выбирается с вероятностью, пропорциональной квадрату расстояния до уже выбранных), затем чередуются
два шага: каждая точка относится к ближайшему центру, каждый центр пересчитывается как среднее
своих точек. Остановка после 100 итераций или при сдвиге центров меньше $10^{-4}$, из трех запусков
берется лучший по $J$. Центры $c_k$ и есть визуальные слова: типичные фрагменты вроде края окна,
купола, участка кирпичной кладки.

### Гистограмма (`BagOfWords.assign_words`, `compute_histogram`)

Метод `assign_words` заменяет каждый дескриптор $x$ изображения номером ближайшего слова:

$$w(x) = \arg\min_k \lVert x - c_k \rVert^2 = \arg\min_k \left( \lVert c_k \rVert^2 - 2\, x \cdot c_k \right),$$

слагаемое $\lVert x \rVert^2$ одинаково для всех слов и не вычисляется. Для матрицы дескрипторов
$X$ размера N × D и словаря $C$ размера K × D все скалярные произведения считаются одним умножением
$X C^T$: получается матрица N × K, в строке $j$ стоят расстояния (без $\lVert x_j \rVert^2$) от дескриптора
$x_j$ до всех слов, номер столбца с минимумом и есть $w(x_j)$. Для CNN перед этим дескрипторы
проецируются той же PCA, что и при построении словаря. Метод `compute_histogram` по N номерам слов
считает гистограмму

$$h_k = \frac{1}{N} \sum_{j=1}^{N} [\, w(x_j) = k \,], \qquad \sum_k h_k = 1 .$$

Нормировка на N делает гистограммы снимков с разным числом точек сравнимыми. Изображение без
дескрипторов дает нулевой вектор.

### Классификаторы (`CLASSIFIERS`)

Перед классификатором (кроме случайного леса) гистограмма преобразуется:

1. Квадратный корень $\varphi(h) = \sqrt{h}$ (ядро Хеллингера). Для двух гистограмм
   $\lVert \sqrt{h} - \sqrt{g} \rVert^2 = 2 \left(1 - \sum_k \sqrt{h_k g_k}\right)$, то есть
   евклидово расстояние после корня выражается через коэффициент Бхаттачарьи, который лучше
   подходит для сравнения распределений. Корень также уменьшает влияние самых частых слов.
2. Стандартизация каждого признака: $z_k = (x_k - \mu_k) / \sigma_k$, где $\mu_k$, $\sigma_k$
   посчитаны по обучающей выборке и сохраняются в модели.

| `--classifier`              | Модель scikit-learn           | Решающее правило                                                                                                                                                                     |
| --------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `linear_svm` (по умолчанию) | `LinearSVC(C=0.01)`           | один против всех: для каждого класса $c$ минимизируется $\frac{1}{2}\lVert w_c \rVert^2 + C \sum_i \max(0, 1 - y_i (w_c \cdot z_i + b_c))^2$, ответ $\arg\max_c (w_c \cdot z + b_c)$ |
| `logreg`                    | `LogisticRegression(C=0.1)`   | $p(c \mid z) = \exp(w_c \cdot z + b_c) / \sum_{c'} \exp(w_{c'} \cdot z + b_{c'})$, минимизируется $-\sum_i \log p(y_i \mid z_i) + \frac{1}{2C} \lVert W \rVert^2$                    |
| `svm`                       | `SVC(kernel='rbf', C=10)`     | ядро $K(z, z') = \exp(-\gamma \lVert z - z' \rVert^2)$, классы попарно (один против одного), голосование                                                                             |
| `rf`                        | `RandomForestClassifier(500)` | 500 деревьев на бутстреп-выборках, голосование                                                                                                                                       |
| `knn`                       | `KNeighborsClassifier(7)`     | 7 ближайших соседей по расстоянию Хеллингера, голоса с весом $1/d$                                                                                                                   |

Малое $C$ означает сильную регуляризацию. Она нужна, потому что признаков (K = 1000) почти столько же,
сколько обучающих изображений (1333).

## Классические методы (OpenCV)

Перед извлечением изображение уменьшается функцией `resize_keep_aspect` и переводится в оттенки
серого. Если большая сторона изображения $\max(w, h)$ длиннее `--image-size` (640 пикселей),
обе стороны умножаются на один и тот же коэффициент

$$s = \frac{640}{\max(w, h)}, \qquad w' = \operatorname{round}(s w), \quad h' = \operatorname{round}(s h),$$

поэтому соотношение сторон $w / h$ сохраняется: снимок 4000 × 3000 становится 640 × 480, снимок
1920 × 1080 становится 640 × 360, портретный 3000 × 4000 становится 480 × 640. Уменьшение делается
с интерполяцией `INTER_AREA` (усреднение пикселей, без муара). Изображения, которые и так не больше
640 пикселей, не меняются: увеличение не добавило бы деталей. Остаются `--nfeatures` (1000) точек
с наибольшим откликом. Метод `detect_and_compute` возвращает только их дескрипторы.

Уменьшение нужно по двум причинам. Размеры снимков в наборе различаются в 20 раз (от 199 × 150
до 4000 × 3000), а параметры детекторов заданы в пикселях, поэтому без приведения к одному масштабу
одна и та же деталь фасада на разных снимках описывается по-разному. Кроме того, на снимке 4000 × 3000
SIFT работает 2.4 с против 0.08 с при 640 пикселях, и обучение с тестом заняли бы больше двух часов.

Проверка размера (SIFT и ORB, `logreg`, K = 1000, остальные параметры по умолчанию):

| `--image-size` | SIFT, test | ORB, test | SIFT, время train + test |
| -------------- | ---------: | --------: | -----------------------: |
| 640            |      0.626 |     0.345 |              15 мин 29 с |
| 1024           |      0.553 |     0.328 |              20 мин 02 с |

При 1024 точность ниже: SIFT по-прежнему оставляет 1000 точек с наибольшим откликом, и на крупном
снимке они уходят на мелкую текстуру (листва, кирпичная кладка, брусчатка), которая повторяется
на снимках разных зданий. При 640 мелкая текстура сглаживается, и точки приходятся на детали
масштаба окон, колонн и куполов, которые и отличают одно здание от другого. Поэтому по умолчанию
выбрано 640.

### SIFT (`SiftExtractor`)

1. Строится пирамида изображений, размытых гауссианами $G(\sigma)$ с растущим $\sigma$.
   Соседние уровни вычитаются: $D(x, y, \sigma) = (G(k\sigma) - G(\sigma)) * I(x, y)$ (разность
   гауссиан). Ключевые точки: локальные экстремумы $D$ по координатам и масштабу. Точки с малым
   контрастом и точки на прямых краях отбрасываются. Масштаб точки дает инвариантность к размеру.
2. В окрестности точки строится гистограмма направлений градиента на 36 бинов, ее максимум задает
   ориентацию точки. Окрестность поворачивается к этой ориентации, что дает инвариантность к повороту.
3. Окрестность делится на сетку 4 × 4, в каждой ячейке считается гистограмма направлений градиента
   на 8 бинов с весами, равными модулю градиента. Дескриптор: $4 \cdot 4 \cdot 8 = 128$ чисел.
4. RootSIFT: $d \leftarrow \sqrt{d / \lVert d \rVert_1}$. После этого евклидово расстояние между
   дескрипторами соответствует ядру Хеллингера, сравнение гистограмм градиентов становится точнее.

### ORB (`OrbExtractor`)

1. Детектор FAST на 8 уровнях пирамиды масштабов: пиксель считается углом, если на окружности
   из 16 пикселей вокруг него есть 9 подряд идущих пикселей, которые светлее или темнее центра больше
   чем на порог (понижен до 10, чтобы находить точки на гладких фасадах). Точки ранжируются мерой
   Харриса.
2. Ориентация задается направлением на центр масс яркости окрестности:
   $\theta = \operatorname{atan2}(m_{01}, m_{10})$, где $m_{pq} = \sum x^p y^q I(x, y)$.
3. Дескриптор rBRIEF: 256 сравнений яркости заранее выбранных пар пикселей $(a, b)$, повернутых
   на угол $\theta$: бит равен 1, если $I(a) < I(b)$.
4. 32 байта дескриптора распаковываются в вектор из 256 нулей и единиц. Для двоичных векторов
   $\lVert a - b \rVert^2$ равно расстоянию Хэмминга, поэтому K-средних в евклидовом пространстве
   корректно группирует такие дескрипторы.

## Нейросетевые модели (PyTorch)

Сеть с весами ImageNet используется без дообучения. Берется выход заданного сверточного слоя
(`--layer`): тензор $C \times h \times w$. Каждая позиция $(i, j)$ карты признаков описывает свой
участок изображения размером около 32 × 32 пикселя входа сети, поэтому карта превращается
в $h \cdot w$ локальных дескрипторов размерности $C$. Дальше они обрабатываются так же, как дескрипторы
SIFT. Сеть работает в режиме `eval()` внутри `torch.no_grad()`, на GPU, если он доступен.

Слой задается явно. Имя слоя по умолчанию записано в конструкторе наследника
(`ResNet50Extractor(layer='layer4')`, `EfficientNetB0Extractor(layer='features.8')`), его можно заменить
аргументом `--layer`, и оно сохраняется в файле модели. В конструкторе `CnnExtractorBase` вызов
`create_feature_extractor(model, return_nodes=[layer])` из `torchvision.models.feature_extraction`
обрезает граф сети после этого слоя. Обрезанная сеть возвращает словарь `{layer: тензор}`,
и метод `get_layer_output` берет из него выход именно этого слоя: `outputs[self.layer]`.
Если слоя с таким именем в сети нет, создание экстрактора завершается ошибкой.

### Предобработка (`CnnExtractorBase.preprocess`)

1. Меньшая сторона изображения приводится к `--input-size` (288 пикселей) с сохранением пропорций
   (`cv2.resize`, при уменьшении `INTER_AREA`). Изображение не обрезается до квадрата: обрезка
   отрезала бы часть здания, а сверточная часть сети принимает вход любого размера.
2. Перестановка каналов BGR в RGB: OpenCV читает BGR, а сети обучены на RGB.
3. Значения переводятся в $[0, 1]$ делением на 255 и нормируются по каналам статистикой ImageNet:
   $x' = (x - \mu) / \sigma$, $\mu = (0.485, 0.456, 0.406)$, $\sigma = (0.229, 0.224, 0.225)$.
   С этой нормировкой обучались веса torchvision.
4. Раскладка $H \times W \times 3$ переставляется в тензор $1 \times 3 \times H \times W$.

### Обработка выхода сети (`CnnExtractorBase.detect_and_compute`)

1. `get_layer_output` возвращает выход слоя `layer`: тензор $C \times h \times w$.
2. Тензор переставляется в матрицу $(h w) \times C$: строка соответствует ячейке карты.
3. Каждая строка нормируется по $L_2$: $d \leftarrow d / \lVert d \rVert_2$. Длина вектора активаций
   зависит от контраста и освещенности участка, после нормировки K-средних сравнивает только
   направление вектора.
4. Классификационная часть сети (глобальное усреднение, полносвязный слой на 1000 классов ImageNet,
   softmax) не используется.

Метод возвращает только матрицу дескрипторов. Ключевых точек у сети нет, а методу BoW нужны только
дескрипторы, поэтому `detect_and_compute` у всех экстракторов возвращает одно и то же: матрицу N × D.

|                            | ResNet-50                                           | EfficientNet-B0                                  |
| -------------------------- | --------------------------------------------------- | ------------------------------------------------ |
| Веса torchvision           | `IMAGENET1K_V2`                                     | `IMAGENET1K_V1`                                  |
| Параметров                 | 25.6 млн                                            | 5.3 млн                                          |
| Слой по умолчанию          | `layer4` (выход последней группы остаточных блоков) | `features.8` (последняя свертка 1 × 1, BN, SiLU) |
| Каналов $C$                | 2048                                                | 1280                                             |
| Шаг карты                  | 32 пикселя                                          | 32 пикселя                                       |
| Дескрипторов на снимок 4:3 | 9 × 12 = 108                                        | 9 × 12 = 108                                     |

### PCA (`BagOfWords.build_vocabulary`, `project`)

Для CNN перед K-средних размерность дескрипторов понижается до 128 (`--pca`). По выборке для словаря
функция `cv2.PCACompute2` находит среднее $\mu$ и 128 собственных векторов ковариационной матрицы
с наибольшими собственными числами (строки матрицы $E$). Каждый дескриптор заменяется проекцией
$y = E (x - \mu)$. Время K-средних и поиска ближайшего слова пропорционально размерности, поэтому
понижение размерности с 2048 до 128 ускоряет их в 16 раз, а каналы сети сильно коррелированы и почти вся дисперсия
остается. Параметры PCA сохраняются в модели и применяются ко всем дескрипторам при тесте и предсказании.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
```

`pip install torch` в Windows ставит сборку PyTorch для CPU, ее достаточно. В Linux pip по умолчанию
ставит сборку с CUDA (несколько гигабайт), сборку для CPU можно поставить до `requirements.txt`:

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
```

Веса сетей torchvision скачивает при первом создании экстрактора (ResNet-50 98 МБ, EfficientNet-B0
21 МБ) в директорию `~/.cache/torch/hub/checkpoints` (в Windows `%USERPROFILE%\.cache\torch\hub\checkpoints`).
Без доступа в интернет файлы `resnet50-11ad3fa6.pth` и `efficientnet_b0_rwightman-7f5810bc.pth`
нужно заранее скопировать в эту директорию.

Модели в `models/` сохранены через joblib с numpy 2.3 и scikit-learn 1.6.1. С numpy 1.x они
не загружаются, другая версия scikit-learn выдает предупреждение о несовпадении версий, поэтому
версия scikit-learn в `requirements.txt` зафиксирована.

## Запуск

Общий вид:

```bash
python main.py [--log-level LEVEL] train   -d <Dataset> -e <метод> -m <модель> [параметры]
python main.py [--log-level LEVEL] test    -d <Dataset> -m <модель> [-o <результаты.csv>]
python main.py [--log-level LEVEL] predict -m <модель> -i <изображение> [-s <директория>] [--no-show]
```

Примеры (набор данных распакован в `Dataset`):

```bash
python main.py train -d Dataset -e efficientnet_b0 -m models/efficientnet_b0.joblib
python main.py test -d Dataset -m models/efficientnet_b0.joblib -o results/efficientnet_b0.csv
python main.py predict -m models/efficientnet_b0.joblib -i photo.jpg -s results

python main.py train -d Dataset -e sift -c logreg -m models/sift.joblib
python main.py train -d Dataset -e orb -c logreg -m models/orb.joblib
python main.py train -d Dataset -e resnet50 -m models/resnet50.joblib
```

В `models/` уже лежат четыре обученные модели (`sift.joblib`, `orb.joblib`, `resnet50.joblib`,
`efficientnet_b0.joblib`), поэтому режим `predict` можно запустить без обучения и без набора данных.
Команды `train` из примеров перезаписывают эти файлы.

В `data/` лежат три изображения из тестовой выборки (часть ExtDataset):

| Файл    | Истинный класс               | Исходный файл в `Dataset/test/ExtDataset`                   |
| ------- | ---------------------------- | ----------------------------------------------------------- |
| `1.jpg` | `02_ChkalovStaircase`        | `02_ChkalovStaircase/v034f144.jpg`                          |
| `2.jpg` | `25_MoscowMSUHighRise`       | `25_MoscowMSUHighRise/9b5b7ab09bf0d0d0c644d7959417052a.jpg` |
| `3.jpg` | `17_MoscowStBasilsCathedral` | `17_MoscowStBasilsCathedral/church_2.jpg`                   |

Модели EfficientNet-B0, ResNet-50 и SIFT классифицируют все три снимка верно. ORB верно
классифицирует только `3.jpg`, `1.jpg` относит к `13_StPetersburgHermitage`,
а `2.jpg` к `21_StPeterKazanCathedral`.

```bash
python main.py predict -m models/efficientnet_b0.joblib -i data/1.jpg -s results
python main.py predict -m models/resnet50.joblib -i data/2.jpg -s results
python main.py predict -m models/sift.joblib -i data/3.jpg -s results
```

Аргументы режима `train`:

| Аргумент             | По умолчанию                  | Описание                                                                                            |
| -------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------- |
| `-d`, `--data`       | обязательный                  | корневая директория набора данных                                                                   |
| `--dataset`          | `landmarks`                   | формат набора данных (загрузчик из `DATA_LOADERS`)                                                  |
| `-e`, `--extractor`  | обязательный                  | `sift`, `orb`, `resnet50`, `efficientnet_b0`                                                        |
| `-m`, `--model`      | обязательный                  | путь для сохранения модели                                                                          |
| `-k`, `--vocab-size` | 1000                          | число визуальных слов K                                                                             |
| `-c`, `--classifier` | `linear_svm`                  | `linear_svm`, `logreg`, `svm`, `rf`, `knn`                                                          |
| `--vocab-images`     | 500                           | число случайных обучающих изображений для словаря                                                   |
| `--max-descriptors`  | 200 000                       | максимум дескрипторов для K-средних                                                                 |
| `--pca`              | 128 для CNN, 0 для SIFT и ORB | размерность PCA перед K-средних, 0 отключает PCA                                                    |
| `--seed`             | 42                            | зерно генератора случайных чисел (выборка для словаря, K-средних)                                   |
| `--image-size`       | 640                           | SIFT, ORB: изображения с большей стороной длиннее этого размера уменьшаются с сохранением пропорций |
| `--nfeatures`        | 1000                          | SIFT, ORB: максимум ключевых точек                                                                  |
| `--layer`            | `layer4`, `features.8`        | CNN: слой сети, выход которого берется как карта признаков                                          |
| `--input-size`       | 288                           | CNN: размер меньшей стороны входа сети                                                              |

Режим `test` принимает `-d`, `--dataset`, `-m` и необязательный `-o`: CSV-файл со столбцами
`path, true, predicted` (путь относительно корня набора). В консоль выводятся точность (accuracy),
отчет по классам (precision, recall, F1) и матрица ошибок.

Режим `predict` принимает `-m`, `-i`, необязательные `-s` (директория для сохранения
`<имя>_with_histogram.png` и `<имя>_histogram.png`) и `--no-show` (не открывать окно). В консоль
выводится предсказанный класс, в окне показывается изображение и его BoW-гистограмма.

Параметры экстрактора задаются только при обучении и хранятся в модели. Ошибки (нет файла или
директории, неверные параметры, несовпадение классов модели и набора) пишутся в лог, скрипт
завершается с кодом 1.

## Результаты

Все замеры сделаны на ноутбуке: Intel Core i7-12700H, 16 ГБ ОЗУ, Windows 11, Python 3.12.4,
OpenCV 4.12.0, scikit-learn 1.6.1, PyTorch 2.12.1 (CPU), torchvision 0.27.1. Сети работали на CPU.

### Точность

Параметры по умолчанию: K = 1000, словарь по 500 изображениям, PCA до 128 для CNN. Для каждого
метода взят лучший классификатор (см. сравнение ниже).

| Метод           | Классификатор | Train |  Test | Macro F1 | Test NNSU (1376) | Test Ext (978) | Время train | Время test |
| --------------- | ------------- | ----: | ----: | -------: | ---------------: | -------------: | ----------: | ---------: |
| ORB             | `logreg`      | 1.000 | 0.345 |    0.309 |            0.334 |          0.361 |  9 мин 33 с | 3 мин 57 с |
| SIFT            | `logreg`      | 1.000 | 0.626 |    0.611 |            0.613 |          0.643 |  8 мин 48 с | 6 мин 41 с |
| ResNet-50       | `linear_svm`  | 1.000 | 0.742 |    0.739 |            0.696 |          0.807 | 11 мин 56 с | 9 мин 39 с |
| EfficientNet-B0 | `linear_svm`  | 1.000 | 0.841 |    0.846 |            0.796 |          0.905 |  6 мин 47 с | 6 мин 37 с |

Лучшая модель: EfficientNet-B0 с линейным SVM, точность 0.841 на 2354 тестовых изображениях.
Время включает чтение изображений: снимки читаются в исходном размере, и декодирование снимков
4000 × 3000 занимает заметную его часть.

### Размер словаря

Точность на тесте при разных K (лучший классификатор для метода). Эксперимент проводился по заранее
извлеченным дескрипторам, сохраненным в float16, на предыдущей версии предобработки (JPEG декодировался
сразу уменьшенным, маленькие снимки для SIFT и ORB увеличивались до 640), поэтому значения при K = 1000
отличаются от таблицы выше не больше чем на 1 п.п.

| K                              |   100 |   300 |   600 |  1000 |  2000 |
| ------------------------------ | ----: | ----: | ----: | ----: | ----: |
| ORB (`logreg`)                 | 0.214 | 0.263 | 0.320 | 0.340 |       |
| SIFT (`logreg`)                | 0.475 | 0.544 | 0.590 | 0.619 | 0.644 |
| ResNet-50 (`linear_svm`)       |       | 0.715 |       | 0.747 | 0.767 |
| EfficientNet-B0 (`linear_svm`) | 0.738 | 0.810 | 0.836 | 0.851 | 0.860 |

Точность растет с K у всех методов, но прирост замедляется. Для распознавания конкретных зданий
нужен крупный словарь: слово должно описывать характерную деталь фасада, а не общий тип текстуры.
Переход от 1000 к 2000 слов дает 1-2.5 п.п., но в 1.6 раза увеличивает время K-средних (для SIFT
с 2.75 до 4.5 мин) и вдвое увеличивает размер гистограмм, поэтому по умолчанию выбрано K = 1000.

Линейные модели с сильной регуляризацией лучше нелинейного SVM и случайного леса: обучающих

### Ошибки

Наборы NNSU и Ext различаются: снимки из интернета сняты с удачных ракурсов и похожи на обучающие
(у классов 13-28 обучающая выборка целиком из интернета), а снимки NNSU часто сделаны вблизи,
под углом или захватывают только часть здания. Поэтому у всех методов точность на Ext выше:
на 3 п.п. у SIFT и ORB, на 11 п.п. у сетей.

Самые частые ошибки EfficientNet-B0:

| Истинный класс             | Предсказанный класс              | Число ошибок |
| -------------------------- | -------------------------------- | -----------: |
| `01_NizhnyNovgorodKremlin` | `14_MoscowKremlin`               |           43 |
| `12_NizhnyNovgorodFair`    | `03_RukavishnikovEstate`         |           18 |
| `01_NizhnyNovgorodKremlin` | `02_ChkalovStaircase`            |           15 |
| `06_ChurchOfTheNativity`   | `14_MoscowKremlin`               |           15 |
| `04_ArkhangelskCathedral`  | `05_PecherskyAscensionMonastery` |           11 |

Пара двух кремлей лидирует у всех четырех методов: красный кирпич, зубчатые стены и башни
дают одинаковые визуальные слова. Чкаловская лестница спускается от стены Нижегородского
кремля, и на многих снимках видны оба объекта. Ярмарка и усадьба Рукавишниковых имеют похожие
светлые фасады с колоннами и лепниной.

### Пример режима predict

Снимок храма Василия Блаженного из тестовой выборки
(`test/ExtDataset/17_MoscowStBasilsCathedral/131030121411.jpg`, в `data/` не входит).
В окне `predict` слева показано изображение с предсказанным классом, справа его BoW-гистограмма.
Пять самых частых слов выделены цветом и подписаны в легенде.

EfficientNet-B0 классифицирует снимок верно. Из 1000 слов встретилось 50, самое частое слово
получило 15% дескрипторов: гистограмма разреженная, несколько слов описывают купола и небо,
характерные для этого снимка.

SIFT на том же снимке ошибается и выдает `14_MoscowKremlin`. SIFT находит 1000 точек, в основном
на мелких деталях: кроне деревьев, узорах куполов, памятнике. Встретилось 535 из 1000 слов, самое
частое слово получило меньше 1% дескрипторов: гистограмма почти равномерная, и выделяющихся слов,
характерных для храма, в ней нет.

### Анализ

1. Признаки сетей точнее классических на 12-50 п.п. Сеть, обученная на ImageNet, описывает
   участок изображения смысловыми признаками (купол, колонна, кирпичная стена) и учитывает цвет.
   SIFT и ORB описывают только распределение яркости серого изображения в маленькой окрестности.
2. EfficientNet-B0 точнее ResNet-50 на 10 п.п., при этом в 5 раз меньше по числу параметров и примерно
   в 2 раза быстрее на CPU.
3. ORB работает плохо. FAST находит углы на ветках, проводах, облаках, а бинарный дескриптор
   из 256 сравнений яркости неустойчив к изменению освещения и ракурса.
4. На обучающей выборке все модели дают точность 1.0, на тесте заметно меньше. Обучающих
   снимков мало (от 17 на класс), а тестовые сняты с других ракурсов и расстояний. Сильная
   регуляризация (малые C у линейных моделей) дала лучший результат, чем нелинейный SVM.
5. BoW не учитывает расположение слов на изображении: небо сверху и брусчатка снизу есть почти
   на каждом снимке и дают много общих слов разным классам.
