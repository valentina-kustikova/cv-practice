

# Отчёт по фильтрам обработки изображений

Лабораторная работа № 1

В этой работе я реализовала восемь фильтров для обработки изображений на Python. Для вычислений использовала библиотеку `NumPy`, а для загрузки и сохранения изображений — `OpenCV`. Каждый фильтр оформлен отдельным классом в файле `image_filters.py`. Запуск программы и выбор фильтра выполняются через `cli.py`.

## Как запустить программу

Программа запускается из командной строки. Например:

```bash
python cli.py --filter antique --input photo.jpg --output antique.jpg --intensity 0.8
```

`--filter` — название фильтра, `--input` — исходная фотография, `--output` — файл, в который нужно записать результат. Остальные настройки необязательные: `--scale` отвечает за масштаб, `--intensity` — за силу эффекта, `--border` — за размер овала, а `--threshold` — за порог выделения контуров.

Сначала `cli.py` считывает параметры с помощью `argparse`. Потом `cv2.imread()` загружает изображение. По имени фильтра вызывается `ImageFilter.get_filter()`, который создаёт объект нужного класса. Метод `apply_filter()` обрабатывает изображение, после чего `cv2.imwrite()` сохраняет результат. Если исходный файл не удалось открыть, программа сообщает об ошибке.

В OpenCV цветное изображение хранится как массив размера `(h, w, 3)`, где `h` — высота, `w` — ширина, а последние три числа описывают синий, зелёный и красный каналы в порядке **BGR**. Каждый канал обычно содержит число от 0 до 255. Во время обработки я часто перевожу массив в `float32`, чтобы можно было работать с дробными коэффициентами. В конце `np.clip(..., 0, 255)` ограничивает значения, а `astype(np.uint8)` возвращает привычный формат изображения.

## 1. Изменение размера — `resize`

Фильтр `Resize` увеличивает или уменьшает изображение в зависимости от параметра `scale`. По умолчанию `scale = 0.5`, то есть ширина и высота уменьшаются примерно вдвое.

Сначала получаю исходные размеры `h` и `w`. Новые размеры вычисляются по формулам:

```text
H' = int(H × s)
W' = int(W × s)
```

где `s` — коэффициент масштаба. После этого нужно понять, какой пиксель исходного изображения поставить в каждую точку нового. Для этого рассчитываются индексы:

```python
row_indices = (np.arange(new_h) / self.scale).astype(np.int32)
col_indices = (np.arange(new_w) / self.scale).astype(np.int32)
result = image[row_indices[:, None], col_indices]
```

Математически выбор исходного пикселя для новой позиции записывается так (при положительном `scale`):

```text
I_new(y, x) = I_old(floor(y / s), floor(x / s))
```

Это простой вариант **метода ближайшего соседа**: готовые цвета берутся из исходной фотографии, новые промежуточные цвета не вычисляются. Поэтому при сильном увеличении можно заметить отдельные квадратные пиксели. `np.arange()` создаёт последовательности индексов, а `[:, None]` помогает правильно совместить индексы строк и столбцов. В коде не предусмотрена отдельная проверка, что `scale` больше нуля, поэтому следует передавать положительное значение.

## 2. Оттенки серого — `gray`

Фильтр `RGB2GrayScale` делает изображение чёрно-белым в смысле оттенков серого. Хотя в названии класса написано RGB, данные из OpenCV я беру в порядке BGR:

```python
b = image[:, :, 0].astype(np.float32)
g = image[:, :, 1].astype(np.float32)
r = image[:, :, 2].astype(np.float32)
```

Вместо обычного среднего арифметического используется формула яркости:

```text
Y = 0.299R + 0.587G + 0.114B
```

У зелёного канала самый большой коэффициент, а у синего — самый маленький. Так лучше учитывается разница в восприятии цветов человеком. Формула применяется ко всем пикселям сразу:

```python
gray = 0.299 * r + 0.587 * g + 0.114 * b
```

На выходе получается уже не цветной массив из трёх каналов, а двумерный массив яркостей `(h, w)`. Значения приводятся к диапазону 0–255 и типу `uint8`.

## 3. Сепия — `antique`

Фильтр `Antique` делает фотографию похожей на старую за счёт тёплых коричневатых оттенков. Этот эффект называется **сепией**. В моём коде здесь меняются только цвета; царапины и шум добавляются другим фильтром.

Чтобы получить сепию, я рассчитываю каждый новый цветовой канал как сумму исходных каналов с коэффициентами:

```text
R' = 0.393R + 0.769G + 0.189B
G' = 0.349R + 0.686G + 0.168B
B' = 0.272R + 0.534G + 0.131B
```

Это можно представить как умножение тройки цветов на матрицу:

```text
[R']   [0.393  0.769  0.189]   [R]
[G'] = [0.349  0.686  0.168] × [G]
[B']   [0.272  0.534  0.131]   [B]
```

Полученные каналы объединяются командой `np.stack([b_new, g_new, r_new], axis=2)` — именно в порядке BGR.

Силу эффекта можно менять параметром `intensity` от 0 до 1. Для этого использую смешивание:

```text
I_result = (1 − k) × I_original + k × I_sepia
```

где `k` — интенсивность. При `k = 0` сохраняются исходные цвета, при `k = 1` полностью применяется сепия, а при `k = 0.5` смешиваются обе версии. После вычислений значения обрезаются до 255, если какой-то канал получился слишком ярким.

## 4. Выцветшие цвета — `fade`

Фильтр `FadeColor` делает фотографию более бледной, как будто её цвета немного выгорели. Для этого я сначала уменьшаю контраст, а потом добавляю светлый тёплый оттенок.

Сила эффекта обозначается `k` (`intensity`). Коэффициент контраста вычисляется так:

```text
c = 1 − 0.7k
```

Затем значения пикселей приближаются к середине диапазона — числу 128:

```text
I_1 = 128 + (I − 128) × c
```

Если пиксель был очень светлым, он становится немного темнее, если очень тёмным — светлее. Поэтому разница между светлыми и тёмными участками уменьшается.

После этого к изображению примешивается цвет `C = [200, 220, 240]` в порядке BGR:

```text
f = 0.5k
I_result = (1 − f) × I_1 + f × C
```

В коде это записано так:

```python
contrast = 1.0 - self.intensity * 0.7
fade = self.intensity * 0.5
img = 128.0 + (img - 128.0) * contrast
img = img * (1.0 - fade) + self.fade_color * fade
```

В конструкторе класса указано `intensity=0.5`, но при запуске через мой `cli.py` по умолчанию передаётся `1.0`. Поэтому для более слабого эффекта нужно указать `--intensity`, например `0.5`.

## 5. Эффект плёнки — `film`

В фильтре `Film` я меняю соотношение цветов, добавляю зернистость и немного снижаю контраст. Это стилизация под плёночную фотографию с необычной, более красной цветопередачей. В комментарии к коду она названа инфракрасной, но настоящие инфракрасные данные здесь не используются.

Пусть `k` — значение `intensity`. Новые каналы вычисляются так:

```text
R' = R × (1 + 0.30k)
G' = G × (1 − 0.30k)
B' = B × (1 − 0.50k)
```

Получается, что красный усиливается, а зелёный и синий ослабляются. При полной интенсивности красный умножается на 1.3, зелёный — на 0.7, синий — на 0.5.

Дальше добавляется случайный шум:

```python
sigma = 12.0 * k
noise = np.random.normal(0.0, sigma, result.shape)
result = result + noise
```

Функция `np.random.normal()` создаёт случайные числа по нормальному распределению со средним 0 и стандартным отклонением `σ = 12k`:

```text
N ~ Normal(0, σ²)
I_2 = I' + N
```

Шум создаётся отдельно для значений цветовых каналов и имитирует зерно плёнки. Затем ещё немного уменьшается контраст:

```text
c = 1 − 0.1k
I_result = 128 + (I_2 − 128) × c
```

При повторном запуске шум может выглядеть иначе, потому что числа выбираются случайно.

## 6. Белая овальная маска — `matte`

Фильтр `Matte` оставляет центральную часть фотографии видимой, а по краям делает белую овальную рамку.

Параметр `border` определяет размер овала: чем он больше, тем меньше остаётся центральная область. `intensity` отвечает за ширину зоны плавного перехода от исходного изображения к белому цвету.

Сначала вычисляю центр изображения и полуоси эллипса:

```text
cx = (W − 1) / 2
cy = (H − 1) / 2
```

```text
rx = max(cx × (1 − b), 1)
ry = max(cy × (1 − b), 1)
```

где `b` — параметр `border`. Для каждого пикселя затем нахожу нормированное расстояние от центра эллипса:

```text
d(x, y) = sqrt( ((x − cx) / rx)² + ((y − cy) / ry)² )
```

Если `d < 1`, точка находится внутри овала, если `d = 1` — на его границе, если `d > 1` — снаружи. Координаты `X` и `Y` получаю через `np.ogrid`, чтобы рассчитать расстояния сразу для всех пикселей.

Внутри овала ближе к его границе создаётся зона плавного перехода к белому цвету. Ширина этой зоны зависит от интенсивности фильтра:

```text
s = 0.30 × k
```

где `k` — параметр `intensity`, принимающий значения от 0 до 1, а `s` — ширина зоны перехода в нормированных координатах.

При положительной интенсивности рассчитываю маску:

```text
t = clip((d − (1 − s)) / s, 0, 1)
```

При `d <= 1 − s` маска равна нулю, при `d >= 1` — единице. Между этими значениями идёт переход. Чем больше интенсивность, тем раньше начинается переход к белому цвету и тем шире становится переходная зона.

Чтобы переход выглядел мягче, использую функцию `smoothstep`:

```text
m = t² × (3 − 2t)
```

Она делает начало и конец перехода менее заметными.

Случай нулевой интенсивности рассматриваю отдельно, чтобы избежать деления на ноль. В этом случае создаю бинарную маску:

```text
m = 0, если d < 1
m = 1, если d >= 1
```

Таким образом, при нулевой интенсивности белая овальная рамка сохраняется, но переход между изображением и рамкой становится резким.

Полученную маску использую в качестве коэффициента смешивания: `α = m`. Итоговый цвет пикселя:

```text
I_result = (1 − α) × I_original + 255 × α
```

Число 255 здесь обозначает белый цвет каждого канала.

При любом значении интенсивности за пределами овала маска равна единице, поэтому эта область становится полностью белой. Изменение интенсивности влияет только на ширину зоны плавного перехода внутри овала, не изменяя размер самого овала и цвет рамки.

## 7. Царапины и потёртости — `scratches`

Этот фильтр создаёт повреждения, похожие на дефекты старой фотоплёнки: тонкие светлые и тёмные царапины, небольшое зерно и отдельные точки. В отличие от сепии, здесь важны случайные координаты, размеры и прозрачность повреждений.

Если количество царапин не задано, оно зависит от интенсивности:

```text
N = int(250k)
```

где `k` — `intensity`. В классе есть дополнительный параметр `count`, но в текущем `cli.py` отдельного аргумента для него нет.

Для каждой царапины случайно выбираются начальная точка `(x0, y0)`, длина, угол, цвет и толщина. Длина берётся примерно до 5% высоты изображения. Угол выбирается из нормального распределения около нуля, поэтому линии чаще направлены вертикально. Смещение конца линии рассчитывается по формулам:

```text
Δx = L × sin(θ)
Δy = L × cos(θ)
```

Чтобы построить линию, используется параметр `t` от 0 до 1:

```text
x(t) = x0 + t × Δx + εx
y(t) = y0 + t × Δy + εy
```

Здесь `εx` и `εy` — небольшие случайные отклонения. Они нужны, чтобы царапина не была идеально прямой. Цвет выбирается белым с вероятностью 70% или чёрным с вероятностью 30%. Толщина обычно составляет 1 пиксель, иногда 2.

Царапины записываются на отдельный слой `scratches`, а их прозрачность — в массив `alpha_map`. Для каждой точки прозрачность немного меняется. Если несколько царапин попадают в одно место, остаётся более сильное значение прозрачности.

Потом я сглаживаю края маски с помощью ядра 3×3:

```text
    [1  2  1]
K = [2  4  2] / 16
    [1  2  1]
```

Это небольшое взвешенное усреднение соседних пикселей маски. После сглаживания слой царапин смешивается с фотографией:

```text
I_1 = (1 − α) × I_original + α × I_scratches
```

Далее добавляется слабый случайный шум со стандартным отклонением `σ = 4k`. Ещё создаются редкие точки-повреждения, количество которых зависит от площади фотографии:

```text
N_points = int(H × W × 0.00008 × k)
```

Эти точки частично смешиваются с чёрным или белым цветом. В конце значения ограничиваются диапазоном 0–255. При новом запуске расположение повреждений будет другим.

## 8. Неоновые контуры — `neon`

Фильтр `Neon` выделяет границы объектов и делает их светящимися. Здесь я сначала нахожу контуры, затем создаю вокруг них несколько слоёв размытого цветного свечения и накладываю всё на затемнённую фотографию.

**Шаг 1. Перевод в серый цвет.** Как и в фильтре `gray`, рассчитываю яркость:

```text
Y = 0.299R + 0.587G + 0.114B
```

Перед поиском контуров изображение немного сглаживается ядром:

```text
     [1  2  1]
K3 = [2  4  2] / 16
     [1  2  1]
```

Это уменьшает влияние мелкого шума, иначе программа могла бы принять его за границы объектов.

**Шаг 2. Поиск границ.** Для этого использую оператор Собеля. Он оценивает изменения яркости по горизонтали и вертикали с помощью двух матриц:

```text
     [−1   0   1]       [−1  −2  −1]
Sx = [−2   0   2]  Sy = [ 0   0   0]
     [−1   0   1]       [ 1   2   1]
```

После применения этих матриц получаются `gx` и `gy` (перепады яркости по двум направлениям). Из них рассчитываю силу границы:

```text
G = sqrt(Gx² + Gy²)
```

Далее сравниваю её с параметром `threshold`:

```text
E(x, y) = 1, если G(x, y) > T
E(x, y) = 0, если G(x, y) ≤ T
```

Здесь `T` — порог. Чем выше порог, тем меньше слабых границ попадёт в результат. На выходе этого шага получается чёрно-белая карта контуров.

**Шаг 3. Размытие контуров.** Создаю ядро 5×5, в котором центральные значения имеют больший вес:

```text
     [ 1   4   7   4   1]
     [ 4  16  26  16   4]
K5 = [ 7  26  41  26   7] / 273
     [ 4  16  26  16   4]
     [ 1   4   7   4   1]
```

Ту же карту границ размываю несколько раз, чтобы получить три слоя:

- `glow_small` — 4 применения ядра, узкое свечение;
- `glow_medium` — 14 применений, более широкое;
- `glow_wide` — 30 применений, самое широкое.

Каждый слой имеет свой оттенок. В коде задаются цвета BGR `[180, 0, 220]`, `[220, 0, 255]` и `[255, 0, 180]`, а также веса 1, 2 и 2.5. Все три слоя складываются:

```text
L = C1 × L_small + 2 × C2 × L_medium + 2.5 × C3 × L_wide
```

Здесь умножение выполняется отдельно для цветовых каналов. Получается яркое фиолетово-розовое свечение разной ширины.

**Шаг 4. Наложение на фотографию.** Исходное изображение затемняется умножением на 0.1:

```text
I_dark = 0.1 × I_original
```

После этого добавляется рассчитанное свечение: `I_1 = I_dark + L`.

Чтобы центральные линии выглядели ярче, карта контуров ещё раз немного сглаживается. Из неё получается `core`, которым результат смешивается с белым цветом:

```text
I_2 = (1 − 0.85 × core) × I_1 + 255 × 0.85 × core
```

В самом конце учитывается `intensity`:

```text
I_result = (1 − k) × I_original + k × I_2
```

Поэтому при небольшой интенсивности остаётся хорошо видна исходная фотография, а при большой сильнее проявляется неоновый эффект.

**Как работает `_convolve`.** Это вспомогательный метод, который я использую для сглаживания и поиска границ. Он добавляет к изображению рамку из нулей (`np.pad`), затем проходит по коэффициентам ядра и суммирует соответствующие сдвинутые участки массива. То есть обработка выполняется без цикла по каждому пикселю, но с циклами по элементам небольшой матрицы. Для симметричных ядер сглаживания это обычная свёртка; в данной реализации ядро перед применением не переворачивается.

В конструкторе `Neon` также объявлена переменная `self.neon_color`, но при вычислении свечения используются цвета, записанные непосредственно в формуле `glow`.

## Примеры команд

Команды ниже рассчитаны на запуск из папки, где находятся `cli.py` и изображение `photo.jpg`:

```bash
python cli.py -f resize -i photo.jpg -o resize.jpg --scale 0.5
python cli.py -f gray -i photo.jpg -o gray.jpg
python cli.py -f antique -i photo.jpg -o antique.jpg --intensity 0.8
python cli.py -f fade -i photo.jpg -o fade.jpg --intensity 0.6
python cli.py -f film -i photo.jpg -o film.jpg --intensity 0.9
python cli.py -f matte -i photo.jpg -o matte.jpg --border 0.15 --intensity 1
python cli.py -f scratches -i photo.jpg -o scratches.jpg --intensity 0.7
python cli.py -f neon -i photo.jpg -o neon.jpg --threshold 50 --intensity 1
```
